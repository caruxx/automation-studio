# レイヤーモーション

Image2 Layout Studio で配置した背景・画像・文字を複製し、固定背景の上で各レイヤーを動かす短い MP4 素材を作る追加機能です。既存の静止画編集、回転アイコン、ビジュアライザー、タイムライン書き出しを維持します。

この文書は実装範囲と操作・保存契約を示します。ソース読み取りによる比較を含みますが、実機操作や MP4 出力の検証完了を示すものではありません。実施した検証と未確認経路は実装完了時の検証記録で確認してください。

最小実装の境界は **Image2 の状態を複製 → 独立したモーション編集 → プロジェクト別保存 → 短尺 MP4 出力**です。背景の再生成や外部 AI 呼出しはこの経路に含めません。

## 操作手順

1. 対象動画の画像画面で **Image2 Layout Studio** を開き、背景と画像・文字レイヤーを用意します。人物などを個別に動かす場合は、それぞれを分けた透過 PNG を配置します。背景に描き込まれた人物が自動で切り抜かれる機能ではありません。
2. **レイヤーモーション**を押します。初めて開くと、開いている Image2 の状態を複製して引き継ぎます。同じページで同じ対象を再度開くと、以前のモーション下書きを再開します。元の Image2 の配置・選択・未保存状態は変更しません。
3. 背景とレイヤー数を確認します。必要なら **背景を変更**、**画像レイヤーを追加**で静止 PNG/JPEG/WebP を読み込みます。文字は複製時の見た目を PNG にしたレイヤーです。背景は固定で、追加したレイヤーの動きも初期値は 0 です。
4. レイヤー一覧から対象を選び、**左右の揺れ（度）**、**上下の揺れ（px）**、**拡縮（%）**、**周期（秒）**、**位相（度）**、**開始（秒）**、**終了（秒）**を調整します。揺れ・拡縮の 3 項目を 0 にすると固定です。一覧の上が手前で、**手前へ**・**奥へ**で順序を変更します。
5. **長さ（秒）**と **fps** を設定します。**再生**・**一時停止**とプレビュー位置のスライダーで冒頭、中間、末尾を確認します。初期値は 6 秒・24 fps。選択枠は出力に含めません。
6. 設定名を入力して **新しく保存**を押します。再開時は「保存済み設定を選択」から選んで **読み込む**を押します。一覧の再取得は **更新**です。未保存のモーション下書きを読み込みで置き換える場合は確認が出ます。Image2 のテンプレート保存とは別の操作です。
7. **MP4 を書き出す**を一度だけ押します。実行中・受付結果不明の間は再実行しません。画面を閉じる前に、プロジェクト名と表示されたジョブ ID または受付 ID を控えます。
8. 「書き出し完了」後、下の動画と **MP4 を開く**で確認します。実ファイルの存在、サイズ、解像度、fps、尺、および複数フレームの背景・レイヤーの見え方を確認してから利用します。今回の MP4 は音声を含みません。

動きの入力範囲は、左右の揺れ −180〜180 度、上下の揺れ −1080〜1080 px、拡縮 0〜50%、周期 0.1〜60 秒、位相 −3600〜3600 度です。開始・終了は全体の長さの範囲内で、UI では終了を開始より後に設定します。表示区間は開始時刻を含み、終了時刻を含みません。動きはレイヤーの中心を基準にします。

**閉じる ×**で閉じても下書きは同じページ内に保持されます。ページの再読込や終了に備えて **新しく保存**を使ってください。未保存時の確認表示は保存そのものではありません。

UI の根拠: [layer-motion.js:134](../web/static/js/layer-motion.js#L134) `ensureRoot`、[layer-motion.js:88](../web/static/js/layer-motion.js#L88) `snapshot`、[layer-motion.js:209](../web/static/js/layer-motion.js#L209) `openLayerMotion`。

独立素材の MP4 を作っただけでは、既存の長尺タイムラインへ自動採用されません。元の背景画像・透過 PNG は再編集のため保持してください。

## 保存先と既存データの保持

対象動画フォルダを `<vol>` とすると、専用データは次の下に保存します。

```text
<vol>/layer_motion/
  projects/    モーションプロジェクトと再開に必要な素材
  exports/     完成した MP4
```

プロジェクトは `projects/motion_<uuid>.json`、完成 MP4 は `exports/motion_<uuid>.mp4` に毎回新規保存します。表示用のプロジェクト名が同じでも既存ファイルを更新しません。背景・各レイヤーは PNG の画像データとして JSON に埋め込み、設定と UI 用メタデータも保持します。元の背景ファイル名だけに依存せず、複製時点の画像から再開できます。自動操作や検証では日時・用途を含む名前を使い、出力との対応を記録します。

書き出しは専用の一時ファイルで進め、完成後に新しい出力先を排他的に確保して確定します。部分出力を完成ファイルとして扱いません。サーバー起動時にこの保存先を自動削除しません。

モーションの保存・書き出しで次の既存ファイルを変更しません。

- vol と channel の `thumbnail_layout_template.json`
- `サムネイル.jpg`、`vol*.jpg`、`vol*.png` などの既存画像
- `vol_timeline.json`、既存の長尺 MP4、音楽ファイル

既存テンプレートの API を新機能の保存に転用しないでください。`POST /api/image-compositor/template` は vol と channel 両方のファイルを上書きし、画像の `src` を 500,000 文字で切ります（[images.py:339](../Python/routers/images.py#L339)、[images.py:353](../Python/routers/images.py#L353)）。

既存 Image2 の `initLayerEditor(name, true)` は状態を初期化し、`loadLayerTemplate()` はレイヤーを置換します（[index.html:13155](../web/static/index.html#L13155)、[index.html:13442](../web/static/index.html#L13442)）。モーションを開くための再初期化やテンプレート再読込を行わないでください。

## 取消と復旧

- **書き出しを中止**は、画面が保持する該当モーションジョブに対して行います。サーバー全体や他の FFmpeg、既存タイムライン書き出しを停止しません。
- 取消要求の送信だけで停止完了とは判断しません。状態を再取得し、取消完了・完了・失敗のどれになったか確認します。取消と完了が競合した場合も最終状態と実ファイルを照合します。
- 通信が切れた、応答が遅い、完了表示が消えた場合は **状態を再確認**を押します。ジョブ ID が分かっている場合は **ジョブ ID で状態を確認**を開き、入力して **確認**を押すこともできます。
- 書き出し開始前に UI が受付 ID（`request_id` の UUID）を発行し、送信内容を固定します。開始応答を受け取れずジョブ ID が不明でも、**状態を再確認**は保持した受付 ID で検索します。通信エラーを「ジョブが作られなかった」という根拠にはしません。
- 受付 ID による状態確認が **404** で、同じページ内に元の送信内容が残っている場合だけ **同じ受付を再送**が表示されます。再送は元の受付 ID・対象・内容のまま行います。状態確認の通信失敗や500エラーでは再送せず、別の受付 ID を作って書き出し直すこともしません。
- 失敗・取消後は保存済みプロジェクトから編集を再開できます。途中ファイルを完成 MP4 として案内しません。再実行する場合は元ジョブが停止したことを確認し、新しい出力として作成します。
- 状態回復のためにアプリや既存サーバーを勝手に再起動しません。保存前の編集内容がある画面を再読込しません。

同じ受付 ID・同じ保存先・同じプロジェクトを再送すると、サーバーは保持している元ジョブを返します。異なる内容で同じ ID を使うと409です。意図的にもう一本書き出す場合だけ新しい受付 ID を使います。根拠: [layer_motion.py:243](../Python/routers/layer_motion.py#L243) `_submit`、[layer_motion.py:284](../Python/routers/layer_motion.py#L284) `status`、[layer-motion.js:479](../web/static/js/layer-motion.js#L479) `poll`。

ジョブ状態と受付 ID の重複防止情報は、サーバーのメモリに最新 100 件を保持します。サーバー再起動・履歴削除後は元のジョブ状態を取得できませんが、保存した JSON と完成 MP4 は残ります。**この場合の404は未受付の証明ではありません。** 記録した出力先とサーバーの状態を確認してから再出力を判断します。同じ ID による重複防止も、メモリから失われた過去ジョブには効きません。

ブラウザはジョブ ID・受付 ID を同じタブのセッションに保存します。プロジェクトの未保存内容と元の送信本文はページ内のメモリだけにあるため、再読込後に受付 ID だけを復元できても **同じ受付を再送**できるとは限りません。保存済みプロジェクトと出力先を先に確認してください。

## チャンネル切替時の保存先

画面を開くと `/context` から対象動画の `scope` を取得し、下書きと保存・読込・書き出しをその保存先に結び付けます。同名の vol が別チャンネルにあっても下書きを分けます。

例: チャンネル A の下書きを編集中に、別画面でチャンネル B へ切り替えた場合、A の画面からの保存・読込・新規書き出しは scope 不一致の **409** で停止します。下書きは保持されるのでページを再読込せず、元の A と対象動画へ戻ってから保存します。現在の保存先と一致する scope の下書きだけを保存し、古い下書きへ B の scope を付け直して保護を回避しません。

開始済みジョブの状態確認・取消と、そのジョブ ID が付いた完成ファイル URL は元の保存先を参照します。チャンネルを切り替えてもジョブの出力先は移りません。根拠: [layer_motion.py:40](../Python/routers/layer_motion.py#L40) `_folder`、[layer-motion.js:209](../web/static/js/layer-motion.js#L209) `openLayerMotion`。

## API 契約

通常操作は UI を使用します。以下は連携・検証用の契約です。対象 `video_name` は画面で確認した vol を明示します。API の `scope` と `request_id` はサーバー上は省略可能ですが、自動操作では省略せず、UI と同じ保護を使います。

| 操作 | API | 入力・応答 |
|---|---|---|
| 対象確認 | `GET /api/layer-motion/context?video_name=...` | `{scope}`。対象フォルダの識別値を取得 |
| 新規プロジェクト保存 | `POST /api/layer-motion/project` | `{video_name,scope,project,title?}` → `{filename,path}` |
| 保存一覧 | `GET /api/layer-motion/projects?video_name=...&scope=...` | `{projects:[{filename,title}]}` |
| 読込 | `GET /api/layer-motion/project?video_name=...&scope=...&filename=...` | `{project,title}` |
| MP4 開始 | `POST /api/layer-motion/export` | `{video_name,scope,project,request_id}` → `{job_id,status,request_id}`。新規時は `queued`、同じ受付の再送時は既存状態。別ジョブ実行中・scope不一致・同ID異内容は409 |
| 状態 | `GET /api/layer-motion/status?job_id=...` または `?request_id=...` | `{job_id,request_id,status,progress,output_path?,url?,error?}`。`progress` は 0–100 |
| 取消 | `POST /api/layer-motion/cancel` | `{job_id}`。このジョブだけを取消対象にする |
| 完成ファイル | `GET /api/layer-motion/file/<video_name>/<filename>?job_id=...` | 成功状態で返された `url` をそのまま利用。ジョブの元 vol に結び付くため、channel 切替後も元出力を参照 |

ジョブ ID を使わない完成ファイル取得では `?scope=...` を付け、現在のチャンネルと対象動画の一致を確認します。

ジョブ状態は `queued` → `running` → `completed`、取消は `cancelling` → `cancelled`、失敗は `failed` です。`cancelling` は停止完了ではありません。

バックエンドの入力範囲は、最大 16 レイヤー、プロジェクト 32 MiB、静止 PNG 各 8 MiB、各辺 8192 px・各画像 16,000,000 画素、入力画像の合計 24,000,000 画素です。API では画像を PNG data URL として渡し、外部 URL やファイルパス、16-bit PNG は受け付けません。8-bit PNG を使用してください。ブラウザで取り込んだ静止 PNG/JPEG/WebP は canvas を通して PNG に変換されます。

出力は最大 1920×1080・偶数寸法、0.1–60 秒、整数 1–30 fps。UI の出力寸法は Image2 の canvas から決まり、上限内の偶数寸法へ調整されます。処理量の上限もあり、超過時は尺・fps、または入力側の画像寸法・レイヤー数を減らします。根拠: [app_layer_motion.py:57](../Python/app_layer_motion.py#L57) `_png`、同 `validate_project`。

## 自動操作契約

自動操作は画面で対象 vol、プロジェクト名、素材を確認してから進めます。既存作品の検証に代えて、専用のダミー背景と透過 PNG、新しいプロジェクト名を使用します。

1. **入力保全**: Image2 の状態を複製し、背景・レイヤーの素材と表示状態を保持します。背景の再生成、元ファイルの削除、既存テンプレートへの保存を行いません。
2. **別名保存**: 検証や新しい作品には一意な名前を付けます。同名がある場合は別名を選び、既存作品の更新と解釈しません。
3. **単一書き出し**: 送信前に `request_id` を発行・保持し、対象 scope と送信内容を固定します。開始操作は一度だけ行い、返されたジョブ識別子も記録します。実行中・応答不明の状態で別 ID の開始操作を行いません。
4. **状態回復**: 開始応答が不明なら保持した受付 ID で状態を取得します。404を確認した場合だけ、元の受付 ID・scope・内容のまま再送できます。通信失敗を根拠に新しい ID を発行しません。再起動・履歴消失が疑われる404では先に出力先を調べます。
5. **完成確認**: `completed` 相当の成功状態だけで終わらず、出力ファイルの存在・非ゼロサイズと ffprobe による動画メタデータを確認します。冒頭・中間・末尾のフレームで固定背景、レイヤー位置、欠落、編集枠の混入を確認します。
6. **取消確認**: 取消対象をジョブ識別子で限定し、終了状態を確認します。既存作品や別処理のプロセスを停止しません。
7. **原本保持**: 元背景・透過 PNG・保存済みプロジェクト・完成 MP4 の場所を記録します。完成後も原本を削除しません。
8. **範囲報告**: 実際に操作・出力確認した機能だけを検証済みとして報告します。ソース読み取り、プレビュー確認、ファイル出力確認を区別します。
9. **対象固定**: scope 不一致409では下書きを保全し、元の対象へ戻るまで保存を止めます。scope を書き換えて別チャンネルへ保存しません。

自動確認に既存 timeline GET を使う場合も注意が必要です。`app_timeline.load()` は旧形式や不足設定を正規化して保存する場合があります（[app_timeline.py:461](../Python/app_timeline.py#L461)、[app_timeline.py:520](../Python/app_timeline.py#L520)）。モーションの独立検証ではこの既存データの移行経路を使いません。

| 経路 | 確認内容 |
|---|---|
| 取込と状態複製 | 背景、透過 PNG、文字、非表示レイヤー、順序を確認。モーション側編集後も元 Image2 の未保存状態が維持されること |
| 動き・時間 | 固定レイヤー、個別設定、振幅ゼロ、異なる周期、再生・停止・シーク、冒頭・中間・末尾を確認 |
| 保存・再開 | 同名表示でも別ファイルになること、背景と素材を含めて再読込できること、既存 template/timeline/画像を変更しないこと |
| MP4 | 成功状態、実ファイル、サイズ、H.264/MP4、解像度、fps、尺、複数フレームの背景固定とレイヤーの見え方を確認 |
| 取消 | 実行中ジョブの取消、終了状態、本ジョブの途中ファイルだけが除去されること、停止確認後の再実行を確認 |
| 通信切断・重複防止 | 受付 ID での状態復旧、二重開始の409、同ID・同内容の再送が同jobになること、404以外で再送しないことを確認 |
| チャンネル切替 | scope不一致409で保存・読込・新規出力を止め、元の下書きが残ること。開始済みjobの状態と完成URLが元volを参照することを確認 |
| 既存機能の回帰 | 元 Image2 の静止編集と、既存タイムラインの表示・保存・書き出しが維持されることを専用データで確認 |

## 受付不明のままページを開き直した場合

要求IDだけが残り、元の送信内容がない状態でサーバー照会も404になると、自動再送はできません。「保存先を確認して編集に戻る」は、`layer_motion/exports` の完成ファイルを確認したうえで、該当下書きの状態記録だけを解除する明示操作です。既存ファイルは削除しません。保存していない画像・設定の下書きそのものはページ再読込を越えて復元できないため、先に「新しく保存」を使ってください。
