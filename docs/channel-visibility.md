# チャンネル一覧の整理（二期）

ヘッダーのチャンネル切替 →「全チャンネルを管理（非表示・再表示）」で、使っていないチャンネルの「非表示」を押す。
再表示するには同じ管理画面の「非表示のチャンネル」を開いて「再表示」を押す。基本設定のチャンネル管理にも非表示ボタンを追加。

非表示は切替一覧、基本設定の一覧、ホームのチャンネル表と制作状況、全チャンネルの制作一覧に反映する。登録、フォルダ、動画、YouTube認証、予約は削除しない。既存の「削除」は登録解除なので表示整理には「非表示」を使う。
選択中のチャンネルは別のチャンネルに切り替えてから操作する。自動運転がONの場合は先に停止する。表示設定は予約や実行中の処理を停止しない。運用状態の全体警告・実行履歴は引き続き確認する。

表示設定はブラウザのlocalStorage `automationStudioHiddenChannels.v1` にチャンネルID配列として保存する。ブラウザ・プロファイル・オリジンごとに独立し、localhostと127.0.0.1も別設定。ブラウザデータ削除で全件表示に戻る。同じオリジンのタブにはstorageイベントで同期する。
保存できなかった場合はエラーを表示する。選択中のチャンネルは古い非表示設定が残っていても表示する。動画エディタや設定フォームを再描画しない。

変更ファイルは `web/static/index.html` と `web/static/js/channel-visibility.js` のみ。静的ファイルのためバックエンド再起動不要。未保存内容を保存してから画面を再読み込みするか、新しいタブで開く。

自動操作契約: 非表示/再表示は管理画面または `setChannelDisplay(channelId, hidden, inManager)` を使う。非表示前にGET `/api/channels/overview` で存在・選択中・自動運転を確認する。DELETEチャンネルAPI、連携解除API、チャンネル切替APIを表示整理に使わない。対象IDをユーザー指定なしに自動選定しない。

検証: 構文検証、保存/再表示/再読込、破損JSON、書込拒否、別タブ通知、選択中・自動運転保護、実際の管理モーダル/設定一覧レンダラー、エディタ保全の隔離テスト通過。稼働中8888のルート/ヘルパー/healthがHTTP 200。追加QA: 正式Chrome154の隔離オリジン127.0.0.1:8899で、本番と同じハンドラ・管理レンダラーを実行し、非表示/再表示、実ページ再読込後の保持、書込拒否、選択中/自動運転ガードをDOMとlocalStorageで実証。ダミーAPI応答を使用し、実登録チャンネルは操作しない。通常8888のホーム/切替導線はAX読み取り済み。通常管理モーダルのAX実表示はアクセシビリティ要素取得が不安定で未確定。
